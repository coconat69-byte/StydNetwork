# 8. `js/data.js` — стартовые данные

[← Оглавление](README.md)

Все стартовые данные проекта в одном месте. Файл используется **дважды**:

1. **Сайт без сервера** берёт данные прямо отсюда (объект `LOCAL` в `api.js`).
2. **Сервер** при первом запуске (или после удаления `back/studnet.db`) читает этот файл и переносит данные в базу (`createDB` в `db.go`).

Поэтому менять данные нужно **только здесь**. После правки удалите `back/studnet.db`, чтобы сервер пересоздал базу.

## Формат

```js
/** комментарий */
const MOCK_DATA = { ...обычный JSON... };
```
Внутри фигурных скобок — **строгий JSON**: кавычки только двойные, без комментариев и без запятой после последнего элемента. Сервер вырезает всё от первой `{` до последней `}` и читает как JSON — любая вольность JavaScript (одинарные кавычки, комментарий внутри) сломает создание базы.

## Поля `MOCK_DATA`

### `accessCodes`
```json
{"123-123-123": 1, "456-456-456": 7, "789-789-789": 6}
```
Код доступа → id пользователя. → таблица `access_codes`.
- `123-123-123` — студент Яша Кузнецов (id 1);
- `456-456-456` — преподаватель и администратор Ольга Сидорова (id 7);
- `789-789-789` — преподаватель Артём Досиксов (id 6).

### `groups`, `directions`
Списки строк для фильтров поиска. → таблицы `study_groups`, `directions`.

### `users`
```json
{
  "id": 1,
  "name": "Яша Кузнецов",
  "email": "yasha.kuznetsov@oatk.ru",
  "avatar": "images/YASHA_KYZHECOV.avif",
  "group": "ИСП361",
  "direction": "Информационные системы и программирование",
  "course": 1,
  "interests": ["Python","Веб-разработка","Java"],
  "online": true,
  "role": "student",
  "bio": "..."
}
```
→ таблица `users`. Поля совпадают с колонками. Необязательные: `isAdmin: true` (доступ к админ-панели), `blocked`, настройки (`showOnline`, `allowMessages`…) — если их нет, берутся значения по умолчанию из `schema.sql`. `role` — `student` или `teacher`: от неё зависит, можно ли писать в каналы и **видны ли чаты групп** (преподавателям — нет).

### `chatTypes`
```json
"channel": {"label":"Канал","readonly":true},
"group":   {"label":"Группа","readonly":false},
...
```
Тип чата → подпись и `readonly` (писать могут только преподаватели). → таблица `chat_types`.

| Тип | Что это | Кто видит |
|---|---|---|
| `channel` | каналы с объявлениями | все; писать — только преподаватели |
| `group` | чат учебной группы | **только студенты** |
| `direction` | чат направления | все |
| `course` | чат курса | все |
| `flood` | флудилка | все |
| `dm` | личная переписка | только двое собеседников |

### `chats`
```json
{"id": 2, "name": "исп341", "type": "group", "avatar": null, "icon": "👥",
 "members": 25, "description": "...", "lastMessage": "...", "lastTime": "11:50"}
```
→ таблица `chats`. У личных чатов (`dm`) нет `name`, зато есть `ownerId` и `userId` — двое собеседников.

### `messages`
```json
"1": [
  {"id": 101, "userId": 7, "text": "...", "time": "10:30", "reactions": [{"emoji":"👍","count":18}]}
]
```
id чата (строкой — в JSON ключи объекта всегда строки) → список сообщений. → таблица `messages` (сервер добавляет каждому поле `chatId`). У сообщений из `data.js` id — 101, 102…; новые сообщения на сервере получат номера дальше по порядку.

### `clubs`
```json
{"id": 1, "name": "IT-клуб ОАТК", "emoji": "💻", "description": "...",
 "category": "IT", "admin": "Ольга Сидорова", "memberIds": [7,1,2,3,5,9,17]}
```
→ таблица `clubs`, а `memberIds` — отдельно в `club_members` (строка на каждого участника).

### `clubMessages`
id клуба → сообщения его чата. → таблица `club_messages` (`reactions` при переносе выбрасываются).

### `reports`
```json
{"id": 142, "userId": 20, "reason": "Спам в чате «Флудилка»", "time": "2 часа назад"}
```
Жалобы на пользователей — видит администратор в разделе «Модерация». → таблица `reports`.

## Как добавить…

- **пользователя** — объект в `users` с новым `id`; чтобы он мог войти — строку в `accessCodes`;
- **чат** — объект в `chats` с новым `id` и существующим `type`;
- **клуб** — объект в `clubs`; участники — в `memberIds`.

Затем удалить `back/studnet.db` и перезапустить сервер.
