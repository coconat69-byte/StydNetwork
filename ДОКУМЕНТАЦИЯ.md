# Документация СтудСети

Этот файл объясняет, как устроен учебный сайт «СтудСеть»: какие файлы за что отвечают, как человек входит в систему и как рисуются экраны. Текст рассчитан на студента колледжа: без сложных терминов, шаг за шагом.

Коды для входа:

- `123-123-123` — студент Яша Кузнецов;
- `456-456-456` — администратор Ольга Сидорова;
- `789-789-789` — преподаватель Артём Досиксов.

---

## 1. Что это за проект

СтудСеть — учебная закрытая соцсеть колледжа. Есть чаты, поиск людей, клубы, профиль, настройки и админ-панель.

Сайт можно открыть двумя способами:

1. **Только браузер.** Открываете `index.html`. Данные берутся из файла `js/data.js`. Изменения (сообщения, клубы) живут до обновления страницы.
2. **С сервером.** В папке `back` запускаете `go run .` и открываете http://localhost:8080. Данные лежат в базе SQLite (`back/studnet.db`).

Фронтенд сам выбирает режим: сначала стучится на сервер, если его нет — переключается на `data.js`.

## 2. Карта файлов

```
StydNetwork/
  index.html          — разметка всех экранов (вход, чаты, поиск, клубы…)
  README.md           — коротко: что это, как запустить
  ДОКУМЕНТАЦИЯ.md     — этот файл

  css/
    variables.css     — цвета, шрифт, размеры (светлая и тёмная тема)
    base.css          — сброс стилей, полосы прокрутки, какой экран виден
    components.css    — кнопки, поля, аватарки, карточки, футер
    screens.css       — внешний вид каждого экрана

  js/
    data.js           — все стартовые данные (пользователи, чаты, клубы)
    api.js            — откуда брать данные: сервер или data.js
    app.js            — рисует интерфейс и обрабатывает клики

  images/             — фотографии профилей

  back/               — сервер на Go и база SQLite
    main.go           — запуск сервера
    api.go            — адреса вида /api/login, /api/chats/...
    db.go             — работа с базой
    schema.sql        — таблицы
```

Скрипты в `index.html` подключаются в конце `body`, в таком порядке:

1. `data.js` — появляется объект `MOCK_DATA`;
2. `api.js` — появляется объект `API` (и запасной `LOCAL`);
3. `app.js` — запускает интерфейс.

Порядок важен: `app.js` вызывает `API`, а режим без сервера читает `MOCK_DATA`.

## 3. Как открывается страница (вход и мигание)

В `<head>` стоит маленький скрипт **до** файлов CSS. Он делает две вещи:

1. Ставит тему (`light` или `dark`) из `localStorage`, чтобы цвета не вспыхивали.
2. Если в этой вкладке уже есть токен входа (`sessionStorage`, ключ `studnet-token`), вешает на `<html>` класс `logged-in`.

Рядом — короткие стили: без класса `logged-in` видно форму входа, с классом — шапку и приложение. Так экран авторизации не мелькает при обновлении.

### Когда нужен код доступа

| Действие | Нужен код? |
|---|---|
| Первый заход / новая вкладка | да |
| Обновление страницы (F5) | нет, токен в `sessionStorage` |
| Закрыли вкладку или браузер и открыли снова | да, `sessionStorage` стёрся |
| Кнопка «Выйти» в настройках | да, токен удаляется специально |

Тема оформления хранится в `localStorage` (`studnet-theme`) — она **не** сбрасывается при закрытии вкладки. Это удобно: светлая/тёмная тема запоминается навсегда, а вход — нет.

## 4. `js/data.js` — данные

Файл выглядит как JSON внутри `const MOCK_DATA = { ... };`. Кавычки только двойные, внутри нет `//` комментариев (кроме шапки файла), чтобы сервер мог вырезать объект и положить его в базу.

Главные поля:

| Поле | Смысл |
|---|---|
| `accessCodes` | код `"123-123-123"` → id пользователя |
| `groups`, `directions` | списки для фильтров поиска |
| `users` | люди: имя, группа, курс, роль (`student` / `teacher`), интересы, `bio`. У администратора ещё `isAdmin: true` |
| `chatTypes` | типы чатов. Если `readonly: true` (канал) — писать могут только преподаватели |
| `chats` | список чатов. У личных (`type: "dm"`) нет названия: есть `ownerId` и `userId` |
| `messages` | ключ — id чата, значение — массив сообщений |
| `clubs` | клубы, `memberIds` — кто состоит |
| `clubMessages` | сообщения чатов клубов |
| `reports` | жалобы для вкладки «Модерация» |

Менять учебные данные нужно **только здесь**. Если работает сервер и база уже создана, удалите `back/studnet.db` и запустите сервер снова — он заново заполнит базу из этого файла.

## 5. `js/api.js` — откуда данные

Объект `API` — единственная «дверь» между интерфейсом и данными. `app.js` не лезет в `MOCK_DATA` напрямую (кроме того, что `LOCAL` внутри `api.js` это делает).

### Два режима

Функция `API.call(сСервера, изФайла)`:

1. Если сервер ещё не признан недоступным — вызывает первый вариант (`fetch` на `/api/...`).
2. Если соединение не удалось — ставит `API.offline = true` и дальше всегда берёт данные из `LOCAL` (`data.js`).
3. Если сервер ответил ошибкой «неверный код» — ошибка показывается человеку, режим не переключается.

Адрес сервера:

- страница открыта с порта `8080` → запросы идут на `/api`;
- иначе (Live Server, файл с диска) → `http://localhost:8080/api`.

### Токен

После успешного входа в `sessionStorage` пишется строка-токен (`studnet-token`). На сервере это настоящий токен. Без сервера — строка вида `local-1`, где `1` — id пользователя.

Каждый запрос к серверу добавляет заголовок `Authorization: Bearer …`.

Объект `LOCAL` повторяет те же действия, что сервер, но в памяти браузера: вход по коду, отправка сообщения, вступление в клуб, блокировка и т.д.

## 6. `js/app.js` — интерфейс

Весь файл обёрнут в `(function () { ... })();` — так переменные не утекают в другие скрипты.

### Данные и состояние

- `DATA` — снимок данных после входа: пользователи, чаты, клубы, типы чатов.
- `state` — где человек сейчас: какой экран, какой чат открыт, какая вкладка клубов и настроек.

`state` (без самого пользователя) пишется в `sessionStorage` при уходе со страницы (`pagehide`) и читается при входе. Поэтому после F5 вы остаётесь в том же чате.

### Помощники

Короткие функции, чтобы не копировать одно и то же:

- `$('селектор')` — найти элемент на странице;
- `esc(текст)` — заменить `<`, `>` и кавычки, чтобы в сообщении нельзя было вставить HTML;
- `userById`, `chatById`, `clubById` — найти объект по id;
- `avatar`, `dot`, `about`, `tags` — куски HTML для карточек людей;
- `onClick(блок, атрибут, функция)` — один обработчик на весь блок: клик по элементу с `data-...` срабатывает даже если элемент нарисовали позже.

### Старт

1. `DOMContentLoaded` → `start()`.
2. Вешаются обработчики (`bindEvents`).
3. Если токена нет — ничего больше не делаем, видна форма входа.
4. Если токен есть — `API.me()` проверяет его, затем `enterApp(user)` загружает данные и рисует приложение.

Выход: стереть `state` и токен, перезагрузить страницу. Так проще, чем вручную чистить все экраны.

### Экраны

Функция `navigate(имя)` показывает секцию `#screen-имя` (класс `is-active`) и вызывает нужный `render...`:

| Экран | Что рисуется |
|---|---|
| `main` | список чатов, переписка, панель справа |
| `search` | фильтры и карточки людей |
| `clubs` | каталог или страница одного клуба |
| `profile` | фото, статус, «о себе», интересы, кнопка «Написать» |
| `settings` | профиль, уведомления, тема, приватность, выход |
| `admin` | обзор, каналы, пользователи, модерация, объявления |

Кнопки с `data-nav="search"` в шапке вызывают `navigate('search')`.

### Чаты

Список слева фильтруется по типу. Клик открывает чат: заголовок, сообщения, можно ли писать. В канал студенту поле ввода прячется.

Личный чат (`dm`) создаётся через `API.openDm`, если его ещё не было.

Отправка сообщения: `API.sendMessage` → обновляется превью в списке → переписка рисуется заново.

### Клубы

«Все» / «Мои» — фильтр по `memberIds`. На странице клуба вкладки «Участники» и «Чат». Писать в чат клуба можно только участникам.

### Настройки

Переключатели (`data-setting`) сразу сохраняются через `API.saveSetting`. Компактный режим вешает класс `compact` на `<html>`. Интересы редактируются отдельно и уходят на сервер вместе с формой «Сохранить».

### Админ-панель

Кнопку «Админ» видит только пользователь с `isAdmin`. Можно создать канал, опубликовать объявление в канал, посмотреть жалобы, заблокировать человека.

## 7. Стили

Четыре файла, каждый со своей задачей. Цвета не прописываются в каждом правиле: они берутся из переменных `--accent`, `--bg`, `--text` в `variables.css`. Для тёмной темы те же имена переменных получают другие значения (`html[data-theme="dark"]`).

Полосы прокрутки тонкие и без стрелок, цвета зависят от темы (`base.css`).

Футер — обычный блок внизу документа: чтобы его увидеть, страницу нужно прокрутить ниже рабочей области (чат как раз занимает высоту окна).

---

## 8. Сервер (`back/`)

Кратко, если запускаете с Go:

- `main.go` поднимает HTTP и отдаёт статику (html, css, js, картинки) плюс `/api/...`;
- `api.go` — вход, данные, сообщения, клубы, админка;
- `db.go` — SQLite;
- при первом запуске, если файла базы нет, сервер создаёт таблицы из `schema.sql` и заполняет их из `js/data.js`.

Авторизация на сервере: после `/api/login` выдаётся токен, дальше он проверяется на каждом запросе.

## 9. Типичный путь клика

Пример: человек нажал «Написать» на карточке в поиске.

1. У кнопки атрибут `data-write="5"` (id Антона).
2. Общий обработчик в `bindEvents` видит `data-write` и вызывает `openDm(5)`.
3. Если личного чата ещё нет — `API.openDm(5)` (сервер или `LOCAL`).
4. `navigate('main')` открывает экран чатов.
5. `openChat(id)` рисует переписку.

Все похожие действия устроены так же: атрибут на HTML → один обработчик → функция → `API` → снова `render`.

---

## 10. Что менять, если нужно доработать

- Новый пользователь, чат, клуб — только `js/data.js` (и пересоздать базу, если сервер уже запускали).
- Новый цвет или отступ — `css/variables.css` или нужный css-файл.
- Новая кнопка на экране — разметка в `index.html`, обработчик в `js/app.js`.
- Новое действие с данными — метод в `js/api.js` (и зеркало в `LOCAL`), при сервере — ещё обработчик в `back/api.go`.
