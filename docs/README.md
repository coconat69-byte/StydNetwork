## 1. Из чего состоит проект

```
StydNetwork/
├── index.html          ← единственная страница сайта (все экраны внутри неё)
├── js/
│   ├── theme.js        ← самый первый скрипт: тема и «уже вошёл?» до отрисовки
│   ├── data.js         ← стартовые данные (пользователи, чаты, клубы…)
│   ├── api.js          ← откуда брать данные: сервер или data.js
│   └── app.js          ← интерфейс: рисует экраны, отвечает на клики
├── css/
│   ├── variables.css   ← цвета и размеры (светлая и тёмная тема)
│   ├── base.css        ← сброс стилей браузера, какой экран виден
│   ├── components.css  ← кнопки, поля, аватарки, таблицы, футер…
│   └── screens.css     ← каждый экран + мобильная версия
├── images/             ← аватарки и иконки
├── back/               ← сервер на Go
│   ├── main.go         ← запуск, список адресов, заголовки безопасности
│   ├── api.go          ← обработчики /api/...
│   ├── events.go       ← мгновенная доставка сообщений
│   ├── db.go           ← работа с базой, создание базы из data.js
│   ├── schema.sql      ← таблицы базы
│   └── studnet.db      ← файл базы (создаётся сам, в git не кладётся)
├── docs/               ← эта документация
└── ДОКУМЕНТАЦИЯ.md     ← краткий обзор проекта
```

Лишние файлы, которые сейчас **не используются** кодом:

- `back/seed.sql` — старый вариант стартовых данных. Сервер его не читает: данные берутся из `js/data.js` (см. [04-back-db.md](04-back-db.md)).
- `back/myapp` — старая собранная программа сервера (от 27.09). Она не знает новых адресов, например `/api/events`. **Запускайте сервер командой `go run .`** или соберите программу заново: `go build -o myapp .`.
- `desktop.ini` — служебные файлы Windows.

## 2. Общая схема

```
 Браузер                                                  Сервер (Go)                База
┌───────────────────────────────┐                        ┌──────────────────┐      ┌───────────┐
│ index.html                    │                        │ main.go          │      │           │
│   theme.js  (тема, logged-in) │                        │  ├ securityHeaders│      │           │
│   data.js   (MOCK_DATA)       │   fetch /api/...       │  ├ allowOtherSites│      │ studnet.db│
│   api.js    (API / LOCAL) ────┼──────────────────────► │  └ mux (адреса)   │      │ (SQLite)  │
│   app.js    (интерфейс)       │ ◄──────────────────────┼─ api.go ──────────┼────► │           │
│                               │   JSON                 │  events.go        │      │           │
└───────────────────────────────┘                        │  db.go ───────────┼────► │           │
                                                         └──────────────────┘      └───────────┘
```

1. Браузер загружает `index.html`. В `<head>` сразу выполняется `theme.js`: ставит тему и, если в этой вкладке уже входили, класс `logged-in` — чтобы не мигала форма входа.
2. В конце `<body>` подключаются `data.js` → `api.js` → `app.js` (именно в таком порядке: каждый следующий пользуется предыдущим).
3. `app.js` по событию `DOMContentLoaded` вызывает `start()`: вешает обработчики кликов и, если есть токен, открывает приложение.
4. Все данные `app.js` получает **только** через объект `API` из `api.js`. `API` сам решает, откуда их взять:
   - есть сервер → запрос `fetch` на `/api/...`, сервер читает/пишет базу и отвечает JSON-ом;
   - сервера нет → те же действия выполняет объект `LOCAL` над данными из `data.js` (в памяти, до обновления страницы).
5. После входа `app.js` запускает `API.listen` — бесконечный цикл «долгого опроса» `/api/events`. Как только кто-то пишет сообщение, сервер отвечает на этот запрос, и сообщение появляется у получателя без обновления страницы (подробно — [03-back-events.md](03-back-events.md)).

## 3. Словарь терминов

| Термин | Что значит |
|---|---|
| **API** | набор адресов сервера `/api/...`, через которые сайт получает и меняет данные. В `api.js` так же называется объект-обёртка над ними |
| **JSON** | текстовый формат данных: `{"name": "Яша", "course": 1}`. Им обмениваются браузер и сервер |
| **fetch** | встроенная функция браузера для запросов к серверу |
| **токен** | случайная строка из 64 символов, которую сервер выдаёт при входе. Браузер прикладывает её к каждому запросу в заголовке `Authorization: Bearer <токен>`, и по ней сервер понимает, кто спрашивает |
| **sessionStorage** | хранилище браузера, которое живёт, пока открыта вкладка (переживает F5, стирается при закрытии вкладки). Там лежат токен и состояние интерфейса |
| **localStorage** | то же, но живёт всегда. Там лежит выбранная тема |
| **обработчик (handler)** | функция на сервере, которая отвечает на один адрес, например `sendMessage` на `POST /api/chats/{id}/messages` |
| **mux** | «маршрутизатор» Go: по методу и адресу запроса выбирает обработчик |
| **XSS** | атака, при которой в страницу подсовывают чужой HTML/скрипт. Защита — функция `esc` в `app.js` и заголовок `Content-Security-Policy` |
| **SQL-инъекция** | атака, при которой в запрос к базе подсовывают кусок SQL. Защита — параметры `?` во всех запросах |
| **долгий опрос (long polling)** | способ мгновенной доставки: браузер спрашивает «что нового?», а сервер не отвечает, пока не появится новое (или не пройдёт 25 секунд) |
| **курсор** | номер последнего события, которое вкладка уже получила. Нужен, чтобы после обрыва связи получить всё пропущенное |
| **режим без сервера** | `API.offline = true`: данные берутся из `data.js`, изменения не сохраняются. Над сайтом видна красная плашка |
| **БЭМ** | правило названий CSS-классов: `блок__элемент--модификатор`, например `chat-item__name`, `btn--primary` |

## 4. Главные правила кода (чтобы не сломать)

1. **Любые данные в HTML — только через `esc(...)`** (`app.js`). Имя, текст сообщения, путь к картинке — всё. Иначе XSS.
2. **Любые значения в SQL — только через `?`** (`api.go`). Никогда не склеивать запрос из строк с данными пользователя.
3. **Любую проверку прав делать на сервере.** То, что кнопка спрятана на сайте, ничего не гарантирует: запрос можно отправить вручную.
4. **Данные менять только в `js/data.js`.** Сервер при создании базы берёт их оттуда же. После правки `data.js` удалите `back/studnet.db`.
5. **Поменяли `schema.sql` — увеличьте `schemaVersion`** в `db.go`, иначе сервер продолжит работать со старой базой.
6. **Правила доступа к чатам — в одном месте:** функция `canSeeChat` в `api.go` и условие `WHERE` в `allData`. Меняйте их вместе (и `LOCAL.data` в `api.js` для режима без сервера).
