## Главное правило: защита от XSS

Экран рисуется так: собираем HTML-строку и кладём её в `innerHTML`. Если вставить в такую строку чужой текст как есть, сообщение `<img src=x onerror=alert(1)>` стало бы настоящей картинкой со скриптом и выполнилось бы у всех, кто его увидел. Поэтому **любое значение из данных** (имя, текст сообщения, название, путь к картинке, даже число) вставляется только через `esc(...)`. Без `esc` можно вставлять только HTML, написанный прямо в этом файле.

## Обёртка и строгий режим

```js
(function () {
  'use strict';
  ...
})();
```
Весь код внутри функции, которая сразу же вызывается. Зачем: переменные и функции (`DATA`, `state`, `render…`) не становятся глобальными, их не видно и не испортить из консоли или из других скриптов. `'use strict'` — строгий режим: опечатка в имени переменной вызовет ошибку, а не тихо создаст глобальную переменную.

## Данные и состояние

```js
let DATA = null;
```
Все данные сайта (то, что вернул `API.data()`): `users`, `chats`, `clubs`, `chatTypes`, `groups`, `directions`. Заполняются в `enterApp`.

```js
const state = {
  user: null,             // кто вошёл
  screen: 'main',         // открытый экран: main, search, clubs, settings, admin, profile
  backTo: 'main',         // куда вернёт кнопка «Назад» в профиле
  profileId: null,        // чей профиль открыт
  chatId: null,           // открытый чат
  chatFilter: 'all',      // фильтр над списком чатов
  chatOpen: false,        // на телефоне: открыта переписка (true) или список чатов (false)
  clubsView: 'all',       // «Все» или «Мои» клубы
  clubId: null,           // открытый клуб
  clubTab: 'members',     // вкладка клуба: members или chat
  settingsTab: 'profile', // вкладка настроек
  adminTab: 'dashboard',  // вкладка админ-панели
};
```
**Где сейчас пользователь.** Все `render…`-функции рисуют экран по `DATA` + `state`. Чтобы что-то поменять на экране, меняем `state` и вызываем нужную `render…`.

### `saveState()`
```js
if (!state.user) return;
const copy = Object.assign({}, state);
delete copy.user;
sessionStorage.setItem(STATE_KEY, JSON.stringify(copy));
```
Вызывается на событии `pagehide` (страница обновляется или закрывается). Кладёт копию `state` **без** пользователя в `sessionStorage` под ключом `studnet-ui`. Пользователя не сохраняем: его всё равно заново спросим у сервера. Если не вошли или выходим (`state.user = null`) — ничего не сохраняем.

### `restoreState()`
Достаёт сохранённое и копирует поля в `state` (`Object.assign`). Испорченный JSON — `catch`, остаются обычные значения. Благодаря этой паре после F5 пользователь остаётся на том же экране, в том же чате и вкладке.

## Помощники

### `$(selector)`
`document.querySelector(selector)` покороче: `$('#chat-list')` — первый элемент по CSS-селектору.

### `esc(text)`
```js
if (text === null || text === undefined) return '';
return String(text)
  .replace(/&/g, '&amp;')
  .replace(/</g, '&lt;')
  .replace(/>/g, '&gt;')
  .replace(/"/g, '&quot;')
  .replace(/'/g, '&#39;');
```
Превращает опасные символы в «HTML-сущности»: `<b>` станет `&lt;b&gt;`, и браузер покажет это как текст. `&` заменяем **первым** — иначе испортили бы уже заменённые `&lt;`. Кавычки — потому что значения вставляются и в атрибуты (`data-user="..."`). `null/undefined` → пустая строка, `String(...)` — числа тоже превращаем в текст.

### `userById(id)`, `chatById(id)`, `clubById(id)`
`DATA.users.find(...)` — объект по `id` или `undefined`.

### `isTeacher(user)`
`user.role === 'teacher'`.

### `inClub(club)`
Есть ли мой id в `club.memberIds` (`|| []` — если списка нет).

### `scrollToBottom(element)`
`element.scrollTop = element.scrollHeight` — прокрутить блок в самый низ, к последнему сообщению.

### `nearBottom(element)`
```js
return element.scrollHeight - element.scrollTop - element.clientHeight < 80;
```
Прокручен ли блок почти до низа (меньше 80 px до конца). `scrollHeight` — полная высота содержимого, `scrollTop` — сколько прокручено, `clientHeight` — видимая высота. Нужно, чтобы новое сообщение не утаскивало вниз человека, который поднялся почитать старые.

### `SETTING_DEFAULTS` и `setting(user, key)`
```js
if (user[key] === undefined || user[key] === null) {
  return SETTING_DEFAULTS[key];
}
return Boolean(user[key]);
```
Включена ли настройка. С сервера приходят `1/0`, без сервера — `true/false`, а если настройку ещё не трогали — её нет вовсе. Функция приводит всё к `true/false` и подставляет значение по умолчанию.

### `canMessage(user)`
Можно ли написать человеку: он разрешил сообщения **или** переписка с ним уже есть (`DATA.chats.some(...)` с `partner(chat)`).

### `plural(n, one, few, many)` и `membersText(n)`
Русское склонение: «1 участник», «3 участника», «25 участников».
- последняя цифра 1, но не 11 → `one`;
- последняя 2–4, но не 12–14 → `few`;
- иначе → `many`.

### `dot(user)`
Точка статуса: `<span class="status-dot status-dot--online">` (зелёная) или без модификатора (серая).

### `avatar(user, size)`
Аватарка размера `xs/sm/md/lg/xl` в обёртке `.avatar-wrap` с точкой статуса в углу. Путь к картинке — через `esc`.

### `about(user)`
Подпись под именем: у преподавателя `Преподаватель · направление`, у студента `группа · N курс · направление`. Пустые части (например, скрытую группу) `filter(Boolean)` выбрасывает, остальные соединяются через ` · `.

### `tags(list)`
Теги-интересы: `<span class="tag">` на каждый непустой элемент.

### `ICON_MESSAGE`, `ICON_SEND`
SVG-иконки «сообщение» и «отправить» строками — вставляются в кнопки.

### `markTab(root, attr, value)`
Подсветить активную кнопку: всем элементам с атрибутом `data-<attr>` внутри `root` ставит класс `is-active`, если значение атрибута равно `value`, остальным — убирает. Используется для вкладок, фильтров, меню.

### `onClick(root, attr, handler)`
```js
root.addEventListener('click', function (e) {
  const element = e.target.closest(`[data-${attr}]`);
  if (element) {
    handler(element.getAttribute(`data-${attr}`));
  }
});
```
**Делегирование событий.** Один обработчик на `root` вместо обработчика на каждую кнопку. `e.target.closest(...)` поднимается от того, по чему кликнули (например, по иконке внутри кнопки), до ближайшего элемента с нужным атрибутом. Плюс: работает и для элементов, нарисованных **позже** (список чатов перерисовывается постоянно, а обработчик вешается один раз).

## Запуск, вход и выход

```js
document.addEventListener('DOMContentLoaded', start);
```
Когда браузер разобрал весь HTML — запускаем `start`.

### `start()`
1. `bindEvents()` — вешаем все обработчики (один раз за жизнь страницы).
2. Нет токена → остаётся форма входа.
3. Есть токен → `API.me()` (проверить, что вход живой) → `enterApp(user)`.
4. Ошибка (токен устарел, сервер пропал) → `API.logout()` стирает токен, убираем класс `logged-in` → снова форма входа.

### `formatCode(e)`
```js
const digits = e.target.value.replace(/\D/g, '').slice(0, 9);
const groups = digits.match(/.{1,3}/g) || [];
e.target.value = groups.join('-');
```
На каждый ввод в поле кода: оставляем только цифры (`\D` — всё, что не цифра), не больше 9, режем по три (`.{1,3}`) и склеиваем через дефис: `123456789` → `123-456-789`.

### `login(e)`
`e.preventDefault()` — форма не перезагружает страницу. `API.login(код)` → `enterApp(user)`. Ошибка («Неверный код…») → `alert`.

### `logout()`
`state.user = null` (чтобы `saveState` ничего не сохранил), стираем сохранённое состояние, `API.logout()`, `location.reload()` — перезагрузка проще всего сбрасывает весь интерфейс.

### `enterApp(user)` — вход выполнен
1. `restoreState()` — вернуть экран, чат, вкладки, как были до обновления.
2. `state.user = user`, `DATA = await API.data()` — все данные.
3. Своя аватарка в шапке. Плашка `#offline-banner` — видна, если `API.offline`. Кнопка «Админ» — только администратору; если сохранён экран `admin`, а человек не админ — переводим на чаты.
4. Варианты для фильтров поиска: `<option>` для каждой группы и направления (через `esc`).
5. Подсвечиваем сохранённые вкладки (`markTab`).
6. Класс `logged-in` (показать приложение) и `compact` (если включён компактный режим).
7. `renderChatFilters()`.
8. Открываем чат, который был открыт, а если его нет — первый в списке. В этом случае на телефоне начинаем со списка (`state.chatOpen = false`).
9. `showChat(state.chatOpen)` — на телефоне показать список или переписку.
10. `navigate(state.screen, state.profileId)` — показать сохранённый экран.
11. `API.listen(onServerEvent)` — **запуск мгновенных сообщений**. Без `await`: цикл крутится в фоне всё время, пока открыта вкладка.

## Обработчики событий

### `bindEvents()`
Вешает **все** обработчики один раз при запуске. По группам:

**Общие**
| Что | Обработчик |
|---|---|
| `pagehide` на `window` | `saveState` |
| `submit` формы входа | `login` |
| `input` в поле кода | `formatCode` |
| клик «Выйти» | `logout` |
| клик по кнопке темы | `setTheme(тёмная ↔ светлая)` |
| клик по любому `[data-nav]` | `navigate(экран)` |

**Люди в любом месте сайта** — один обработчик на весь `document`:
```js
const write = e.target.closest('[data-write]');
const person = e.target.closest('[data-user]');
const back = e.target.closest('[data-back]');
if (write) openDm(...)
else if (person) navigate('profile', ...)
else if (back) navigate(state.backTo);
```
Порядок важен: кнопка «Написать» лежит **внутри** карточки человека (`data-user`), поэтому сначала проверяем `data-write` — иначе клик по кнопке открыл бы профиль.

**Чаты**
- `[data-filter]` в фильтрах → `state.chatFilter`, подсветка, `renderChatList`.
- `[data-chat]` в списке → `openChat(id)` и `showChat(true)` (на телефоне — открыть переписку).
- `#chat-back` → `showChat(false)` (на телефоне — к списку).
- `submit` формы сообщения → `sendMessage`.

**Поиск**
- ввод в строку поиска в шапке → если уже на экране поиска, `renderSearch`, иначе `navigate('search')`;
- изменение любого фильтра → `renderSearch`;
- «Сбросить» → очистить строку и фильтры, `renderSearch`.

**Клубы**
- `[data-clubs-view]` («Все / Мои») → `renderClubs`;
- `[data-club]` (карточка) → открыть клуб на вкладке «Участники», прокрутить наверх;
- `[data-club-back]` → к каталогу;
- `[data-club-toggle]` → `toggleClub`;
- `[data-club-tab]` → переключить вкладку, `renderClubTab`;
- `submit` в странице клуба → `sendClubMessage`.

**Настройки**
- `[data-settings]` → вкладка, `renderSettings`;
- `[data-set-theme]` → `setTheme`;
- `[data-setting]` (переключатель) → `toggleSetting`;
- `submit` → `saveProfile`;
- интересы: `[data-remove-interest]` → убрать, `[data-pick-interest]` → добавить подсказку, `[data-add-interest]` → добавить из поля; Enter в поле `#interest-input` добавляет интерес (`preventDefault` — а не отправляет всю форму).

**Админ-панель**
- `[data-admin]` → вкладка (и сброс редактирования канала), `renderAdmin`;
- `submit` → `saveChannel` или `postAnnouncement` в зависимости от `id` формы;
- `[data-edit-channel]`, `[data-cancel-edit]` → режим редактирования канала;
- `[data-block]` → `toggleBlock`, `[data-dismiss]` → `dismissReport`.

## Навигация и тема

### `navigate(screen, profileId)`
1. Если открываем профиль: запоминаем, откуда пришли (`backTo`), и чей профиль (`profileId || свой`).
2. `state.screen = screen`.
3. Всем `.screen` ставим/снимаем `is-active` — виден только `#screen-<имя>`.
4. Подсвечиваем пункт меню, прокручиваем окно наверх.
5. Рисуем экран: `renderProfile` / `renderSearch` / `renderClubs` / `renderSettings` / `renderAdmin`. Экран чатов не перерисовывается — он живёт всё время и обновляется сам.

### `theme()`
Текущая тема из `<html data-theme="...">`.

### `setTheme(value)`
Ставит `data-theme` (цвета меняются мгновенно — CSS-переменные), запоминает в `localStorage` (навсегда, см. `theme.js`), и если открыты настройки — перерисовывает выбор темы.

## Чаты

### `partner(chat)`
Собеседник в личном чате: если я `ownerId` — собеседник `userId`, и наоборот. У остальных чатов — `undefined`.

### `chatName(chat)`, `chatPicture(chat)`
Название и картинка чата: у личного — имя и фото собеседника; у остальных — свои название, картинка или эмодзи (`💬` по умолчанию).

### `typeLabel(chat)`, `typeBadge(chat)`
Подпись типа («Канал», «Группа»…) из `DATA.chatTypes` и цветной ярлык `<span class="chat-type chat-type--channel">`.

### `canWrite(chat)`
В чаты с `readonly` (каналы) могут писать только преподаватели. Это только для интерфейса — настоящая проверка в `sendMessage` на сервере.

### `renderChatFilters()`
```js
const types = Object.keys(DATA.chatTypes).filter(function (type) {
  return type !== 'group' || !isTeacher(state.user);
});
if (state.chatFilter !== 'all' && !types.includes(state.chatFilter)) {
  state.chatFilter = 'all';
}
```
Кнопки «Все» + по одной на каждый тип чата. **Преподавателю кнопку «Группа» не показываем** — чаты групп сервер ему не отдаёт. Если сохранённый фильтр стал недоступен — сбрасываем на «Все».

### `showUnread(chat)`
Показывать ли счётчик непрочитанных: для каналов — настройка `notifyChannels`, для остальных — `notifyUnread`.

### `renderChatList()`
Список чатов с учётом фильтра. Для каждого — картинка, название, время, превью последнего сообщения (или «Нет сообщений»), ярлык типа и счётчик непрочитанных. Открытый чат подсвечен классом `is-active`. Атрибут `data-chat="id"` — по нему ловится клик.

### `openChat(chatId)`
1. Запоминает `state.chatId`, перерисовывает список (подсветка).
2. Заголовок и подпись «Тип · N участников» через `textContent` — он вставляет только текст, поэтому `esc` не нужен.
3. Поле ввода или плашка «только чтение» — по `canWrite`.
4. `await loadMessages(chat, true)` — сообщения с прокруткой в самый низ.

### `loadMessages(chat, toBottom)`
```js
const messages = await API.messages(chat.id);
if (state.chatId !== chat.id) return;
```
1. Загружает сообщения. Если пока грузили, человек открыл **другой** чат — результат выбрасываем, чтобы старый чат не «перепрыгнул» поверх нового.
2. Чат открыт → прочитан: обнуляем счётчик и сообщаем серверу `API.markRead` (ошибку игнорируем — отметится в следующий раз).
3. ```js
   const stick = toBottom || nearBottom(box);
   box.innerHTML = messagesHtml(messages);
   if (stick) scrollToBottom(box);
   ```
   Запоминаем **до** перерисовки, был ли человек внизу. После — прокручиваем вниз, только если нужно: при открытии чата всегда, при новом сообщении — только если человек и так был внизу.
4. `renderChatInfo` — панель справа.

### `showChat(open)`
`state.chatOpen = open` и класс `is-chat-open` на `.chat-layout`. На компьютере ничего не меняет, а на телефоне (`@media` в `screens.css`) переключает «список ↔ переписка».

### `reactionsHtml(reactions)`
Реакции под сообщением: `👍 3  🔥 2`.

### `messageHtml(msg, myName)`
Одно сообщение:
- **своё** (`msg.userId === я`) — класс `message--own`: справа, синее, без аватарки и имени;
- **чужое** — аватарка и имя автора с `data-user` (клик → профиль);
- **упоминание** — если в чужом сообщении есть моё имя и включена настройка «Упоминания», класс `message--mention` подсвечивает его.

Текст, имя, время — через `esc`.

### `messagesHtml(messages)`
Все сообщения или «Сообщений пока нет. Напишите первым!». `myName` — имя без фамилии в нижнем регистре (`«яша»`), считается один раз для всех сообщений.

### `personHtml(user, extraClass)`
Человек строкой: аватарка, имя, группа (или «Преподаватель»). `data-user` — клик открывает профиль.

### `renderChatInfo(chat, messages)`
Панель справа: название, ярлык типа, описание и люди. В личном чате — двое собеседников, в остальных — все, кто писал. `new Set(ids)` убирает повторы (один человек мог написать много сообщений).

### `sendMessage(e)`
1. `preventDefault` — не перезагружать страницу.
2. Пустой текст или нет чата → ничего.
3. `API.sendMessage` → ошибка («только чтение», «нет связи») → `alert`, поле не очищаем.
4. Очищаем поле, обновляем превью в списке и перерисовываем чат (`openChat`).

Получатели увидят сообщение через мгновенную доставку (см. ниже). Сам отправитель тоже получит событие о своём сообщении — это нужно, если у него открыта вторая вкладка.

### `openDm(userId)`
1. Ищет личный чат с этим человеком в `DATA.chats`.
2. Нет → `API.openDm` (сервер создаст) и добавляет в список. Ошибка («ограничил личные сообщения») → `alert`.
3. Фильтр «Все» (чтобы чат точно был виден), экран чатов, открыть чат, на телефоне — показать переписку.

## Мгновенные сообщения

Как событие попадает в браузер — см. [03-back-events.md](03-back-events.md) (сервер) и [06-front-api.md](06-front-api.md) (`API.listen`). Здесь — что с ним делает интерфейс.

### `onServerEvent(event)`
Распределяет события по типам:
| `event.type` | Функция |
|---|---|
| `message` | `onNewMessage(event.chatId, event.message)` |
| `club` | `onNewClubMessage(Number(event.clubId))` — `Number`, потому что сервер присылает id клуба строкой |
| `resync` | `resync()` |

### `onNewMessage(chatId, msg)`
```js
const chat = chatById(chatId);
if (!chat) {
  reloadChats();
  return;
}
chat.lastMessage = msg.text;
chat.lastTime = msg.time;
if (chatId === state.chatId) {
  loadMessages(chat, msg.userId === state.user.id);
} else if (msg.userId !== state.user.id) {
  chat.unread = (chat.unread || 0) + 1;
}
renderChatList();
```
1. **Чата нет в списке** — значит, нам впервые написали в личку. Перечитываем список чатов с сервера (`reloadChats`) — новый чат появится со счётчиком.
2. Обновляем превью: текст и время последнего сообщения.
3. **Этот чат сейчас открыт** → перечитываем его сообщения (`loadMessages`). Если сообщение моё — прокручиваем вниз всегда, если чужое — только если я и так был внизу. `loadMessages` заодно отметит чат прочитанным.
4. **Другой чат** и сообщение чужое → счётчик непрочитанных +1.
5. Перерисовываем список — превью и счётчик обновляются на глазах.

### `onNewClubMessage(clubId)`
Если открыт экран клубов, именно этот клуб и вкладка «Чат клуба» — `refreshClubChat`. Иначе ничего: клубный чат загрузится свежим при открытии.

### `reloadChats()`
`API.data()` и замена `DATA.chats` и `DATA.users` на свежие (в новой личке может быть новый собеседник). Ошибка — список остаётся прежним.

### `resync()`
«Перечитать всё» — после перезапуска сервера, долгого обрыва связи или со старым сервером без `/api/events`: `reloadChats`, перечитать открытый чат (без прокрутки) и открытый клубный чат.

## Поиск

### `userCardHtml(user)`
Карточка: аватарка, имя, `about`, первые три интереса и кнопка «Написать» (или «Не принимает сообщения»).

### `renderSearch()`
Читает строку поиска и фильтры, отбирает людей:
- не себя;
- имя содержит строку поиска (без учёта регистра);
- группа совпадает (без учёта регистра: в фильтре «исп341», у людей «ИСП341»);
- направление, курс (`Number('')` = 0 — «Все курсы»), «Только онлайн».

Пишет число найденных в `#search-count` и рисует карточки (или «Никого не нашли»).

## Клубы

### `clubCardHtml(club)`
Карточка в каталоге: эмодзи-баннер, название, описание, число участников, «Вы в клубе» и категория.

### `renderClubs()`
Открыт клуб (`state.clubId`) → прячет каталог, рисует страницу клуба. Иначе — каталог: все клубы или только мои (`state.clubsView`).

### `renderClubPage(club)`
Шапка клуба (эмодзи, название, описание, категория, число участников, руководитель), кнопка «Вступить в клуб» / «Выйти из клуба», вкладки «Участники / Чат клуба» и место для их содержимого `#club-tab`.

### `renderClubTab(club)`
- **Участники** — карточки людей (`personHtml(..., 'person--card')`) или «В клубе пока никого нет».
- **Чат клуба** — загружает сообщения (и проверяет, что пока грузили, не открыли другое), рисует ленту и под ней поле ввода — только участникам; остальным «Вступите в клуб, чтобы писать в чат».

### `refreshClubChat(club)`
При новом сообщении в открытом клубном чате перерисовывает **только ленту**, а не поле ввода — чтобы не стереть то, что человек сейчас набирает. Прокрутка вниз — если был внизу.

### `toggleClub()`
`API.toggleClub` → новый список участников в `club.memberIds` → перерисовать страницу клуба.

### `sendClubMessage(e)`
Отправляет текст из `#club-input`, перерисовывает вкладку и возвращает курсор в поле.

## Настройки

### Интересы
- `myInterests` — интересы, пока человек редактирует профиль. Сохраняются только кнопкой «Сохранить». `MAX_INTERESTS = 10` — как на сервере.
- `suggestedInterests()` — подсказки: интересы всех людей, посчитанные (`count`), без уже выбранных, самые популярные первыми, не больше 15.
- `addInterest(text)` — обрезает до 30 символов, пропускает пустые и повторы (без учёта регистра), не больше 10 (`alert`), добавляет и перерисовывает блок.
- `removeInterest(item)` — убрать из списка.
- `renderInterests()` — перерисовывает **только** блок интересов (`#interests-editor`): выбранные теги с ✕, поле «Свой интерес» с кнопкой и подсказки «+ …». Только его — чтобы не стереть то, что человек уже ввёл в других полях формы.

### `saveProfile(e)`
Собирает имя, почту, «о себе» и `myInterests` → `API.updateMe`. Ошибку показывает `alert`. Успех → обновляет себя и в `state.user`, и в `DATA.users` (там имя видят чаты, поиск, клубы), перерисовывает и пишет «✓ Изменения сохранены».

### `toggleRow(key, label, description)`
Строка настроек с переключателем `<div class="toggle" data-setting="key">`. Все тексты — наши собственные, поэтому `esc` не нужен.

### `toggleSetting(key)`
Новое значение = противоположное текущему → `API.saveSetting` → записать в `state.user` и `DATA.users` → `applySettings` и перерисовать.

### `applySettings()`
Применить сразу: класс `compact` на `<html>`, перерисовать список чатов (счётчики) и открытый чат (подсветка упоминаний).

### `themeOption(value, label)`
Карточка выбора темы с превью; активная — `is-active`.

### Панели вкладок
- `profilePanel(user)` — форма: имя (`maxlength=50`), почта (100), группа (только чтение), «о себе» (500), интересы, «Сохранить». Ограничения — как на сервере.
- `notificationsPanel()` — «Новые сообщения», «Объявления», «Упоминания».
- `appearancePanel()` — тема и компактный режим.
- `privacyPanel()` — «Показывать статус онлайн», «Показывать группу», «Разрешить личные сообщения».

### `renderSettings()`
Рисует панель выбранной вкладки; если это «Профиль» — заполняет `myInterests` текущими интересами и рисует их блок.

## Админ-панель

Кнопку «Админ» видит только администратор, но настоящая проверка — на сервере (`adminOnly`).

- `editingChannelId` — какой канал сейчас редактируется (`null` — форма создаёт новый).
- `table(headers, rows)` — HTML-таблица. Ячейки должны быть **уже безопасным** HTML (с `esc` там, где данные).
- `stat(value, label)` — карточка с цифрой.
- `userLink(user)` — имя-ссылка на профиль (или «Удалённый пользователь»).
- `blockButton(user)` — «Заблокировать» / «Разблокировать»; у админа — надпись «Администратор».
- `allChannels()` — чаты с типом `channel`.

### Вкладки
- `dashboardTab()` — `API.adminStats` → 4 карточки.
- `channelsTab()` — форма «Новый канал» / «Редактирование: …» (с «Отмена») и таблица каналов с кнопкой «Редактировать».
- `usersTab()` — все пользователи: имя, почта, группа, роль, статус, кнопка блокировки.
- `moderationTab()` — `API.reports` → таблица жалоб с «Отклонить» и «Заблокировать» (или «Жалоб нет 🎉»).
- `announcementsTab()` — форма «Новое объявление» (выбор канала, текст) и все сообщения всех каналов, новые сверху. Сообщения каналов загружаются **параллельно** (`Promise.all`), а не по очереди.

### `renderAdmin()`
Рисует выбранную вкладку. Если пока грузили данные, человек переключил вкладку — старое не рисуем.

### Действия
- `saveChannel(form)` — `updateChannel` или `createChannel`, обновить `DATA.chats`, сбросить редактирование, перерисовать список чатов и админку.
- `postAnnouncement(form)` — сообщение в выбранный канал через обычный `API.sendMessage` (получатели увидят его мгновенно), обновить превью.
- `toggleBlock(userId)` — подтверждение `confirm(...)` (показывает обычный текст, а не HTML, поэтому имя тут безопасно), `API.blockUser`, отметить локально, перерисовать.
- `dismissReport(reportId)` — `API.dismissReport`, перерисовать.
